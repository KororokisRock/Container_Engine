# Container Runtime Engine

## Описание

Данный проект представляет собой низкоуровневый container runtime, написанный на языке C. Целью проекта является реализация механизма запуска изолированных процессов/контейнеров с использованием системных вызовов ядра Linux.

Проект ориентирован на изучение фундаментальных принципов контейнеризации: Namespaces, Control Groups (cgroups) v2 и OverlayFS. Движок спроектирован как Rootless-решение, позволяющее запускать контейнеры без прав суперпользователя.

## Архитектура

В основе проекта лежит принцип разделения ответственности:

1. **Движок (Core Engine):** Выполняет непосредственную изоляцию процесса через Namespaces, настройку cgroups и монтирование файловой системы.
2. **Менеджер (Container Manager):** Компонент планируется к разработке в будущем. Он будет отвечать за оркестрацию, хранение списка запущенных контейнеров (команда `list`) и управление их жизненным циклом. В текущей версии данный функционал не реализован.

### Технические особенности

* **Изоляция:** Используются системные вызовы `clone()` с флагами `CLONE_NEWPID`, `CLONE_NEWNET`, `CLONE_NEWNS`, `CLONE_NEWUTS`, `CLONE_NEWUSER`.
* **Управление ресурсами:** Применяется делегирование cgroups v2 для ограничения памяти и количества процессов.
* **Файловая система:** Реализована поддержка OverlayFS. При запуске движок автоматически создает временную структуру директорий (`upper`, `work`, `merged`) в `/tmp/container_<PID>`, используя переданный путь `--rootfs` как `lowerdir`.

## Использование

Движок поддерживает подкоманды для управления контейнером.

### Шаблон запуска

```bash
./<binary_name> <command> [options] [target_cmd]

```

Пример вызова:

```bash
./test run --rootfs /path/to/rootfs --hostname container_name --memory 100m --pids 20 /bin/sh

```

**Описание аргументов:**

* `<command>`: Подкоманда. В текущей версии доступна только `run`.
* `--rootfs`: Путь к директории с базовой файловой системой.
* `--hostname`: Имя хоста внутри контейнера.
* `--memory`: Лимит оперативной памяти (например, `100m`).
* `--pids`: Максимальное количество процессов.
* `[target_cmd]`: Команда для выполнения внутри контейнера (например, `/bin/sh`).

## Сборка

Для сборки проекта используется `make`. Доступны следующие режимы:

* `make BUILD_MODE=test`: Сборка с отладочными символами и санитайзерами (AddressSanitizer, UndefinedBehaviorSanitizer).
* `make BUILD_MODE=prod`: Сборка с оптимизацией `-O2`.

## Статус реализации

| Функциональность | Статус |
| --- | --- |
| Команда `run` | Реализовано |
| Команда `exec` | В планах |
| Режим `detach` | В планах |
| Network Namespaces | В планах |
| Менеджер контейнеров | Не реализовано (планируется отдельно) |

## Примечание по окружению

Движок использует прямой доступ к cgroups v2. В некоторых средах (например, WSL2) стандартные права пользователя могут быть ограничены. В таких случаях для корректной работы необходимо обеспечить делегирование иерархии cgroups пользователю (например, через запуск в рамках `systemd-run --user --scope`). При работе в нативной среде Linux движок функционирует напрямую при наличии прав доступа к cgroupfs.
